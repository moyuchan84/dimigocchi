# 디미고 해킹방어과 입시 준비 사이트 — 개발계획서

- 문서 버전: v1.0 (2026-07-30)
- 개발 방식: **Claude Code**를 이용한 페어 개발 (본 문서 + 유즈케이스명세서 + 요구사양서를 프로젝트 컨텍스트로 제공)
- 관련 문서: 01_유즈케이스명세서.md, 02_요구사양서.md

---

## 1. 목표 요약

요구사양서(02)에 정의된 기능을 갖춘 **static 학습 웹사이트**를 만들어 Vercel에 배포한다. 서버·DB 없이 콘텐츠(이론/문제/면접질문)는 마크다운·JSON 파일로 관리하고, 학습 진도·모의고사 결과는 브라우저 localStorage에 저장한다.

## 2. 기술 스택 선정

| 영역 | 선택 | 근거 |
|---|---|---|
| 프레임워크 | **Astro** | 콘텐츠 중심 static 사이트에 최적화(Content Collections로 마크다운/JSON을 타입 안전하게 관리), 기본이 정적 HTML 출력이라 "static으로 작성"이라는 요구에 정확히 부합, Vercel 공식 어댑터(`@astrojs/vercel`) 지원, 필요한 화면(모의고사 타이머/채점 등)만 React 아일랜드로 부분 하이드레이션 가능 |
| 인터랙티브 컴포넌트 | React (Astro Islands, `client:load`) | 모의고사 엔진, 타임어택 타이머, 대시보드 진행률 위젯 등 상태가 필요한 부분에만 적용 |
| 스타일 | Tailwind CSS | 빠른 반응형 UI 구현, Astro 공식 통합(`@astrojs/tailwind`) |
| 콘텐츠 관리 | Astro Content Collections (Markdown + JSON, `content/config.ts`로 zod 스키마 검증) | 요구사양서 7장 데이터 모델을 코드로 강제(스키마 오류를 빌드 타임에 검출) |
| 상태/로컬 저장 | 커스텀 훅(`useLocalStorage`) | 요구사양서 NFR-5 (서버 없이 localStorage만 사용) |
| 검색 | 클라이언트 사이드 인덱스 (Pagefind 또는 자체 JSON 인덱스 + Fuse.js) | 정적 사이트에서 서버 없이 빠른 검색 구현 |
| 배포 | Vercel (GitHub 연동 자동 배포) | 사용자 요구사항(Vercel 배포)에 직접 부합, Astro 공식 지원 |
| 저장소/버전관리 | GitHub | Vercel 자동 배포 트리거, 콘텐츠 변경 이력 관리 |

> 대안으로 Next.js(App Router, `output: 'export'`)도 가능하나, 이 프로젝트는 인터랙티브 앱보다 "콘텐츠+약간의 인터랙션" 성격이 강해 Astro가 더 가볍고 목적에 부합한다. Claude Code로 개발 중 Astro의 학습곡선이 부담되면 언제든 Next.js static export로 전환 가능하도록 콘텐츠(마크다운/JSON) 스키마는 프레임워크 비종속적으로 설계한다.

## 5. Claude Code 활용 가이드

### 5.1 CLAUDE.md 작성 권장
프로젝트 루트에 `CLAUDE.md`를 두고 아래 내용을 요약해 명시하면, 매 세션마다 반복 설명 없이 일관된 개발이 가능하다.
```md
# 프로젝트: 디미고 해킹방어과 입시 준비 사이트
- 기술스택: Astro + React(Islands) + Tailwind, Vercel 배포, 서버 없음(static)
- 데이터: 학습 진도/결과는 localStorage에만 저장 (서버 전송 금지)
- 콘텐츠는 src/content 아래 Markdown/JSON으로 관리, 코드 로직과 분리
- 상세 기획: 01_유즈케이스명세서.md, 02_요구사양서.md, 03_개발계획서.md 참고
- 실제 저작권 있는 기출문제 원문 게재 금지, 자체 제작 문제만 사용
- 해킹 관련 콘텐츠는 "개념 이해/방어적 관점" 중심, 공격 실습 코드 작성 금지
```

### 5.2 단계별 프롬프트 예시
- **P0~P1**: "02_요구사양서.md의 5장 사이트맵대로 Astro 프로젝트에 페이지 라우팅과 기본 레이아웃(Header/Nav/Footer)을 만들어줘. Tailwind 적용해줘."
- **P2**: "src/content/config.ts에 02_요구사양서.md 7장의 이론 챕터/문제/면접질문/일정 스키마를 zod로 정의해줘. 이론 챕터 샘플로 '네트워크 기초 - OSI 7계층' 1편을 6.2절 내용을 참고해서 작성해줘."
- **P3**: "요구사양서 FR-3 요구사항대로 모의고사 응시 컴포넌트를 React로 만들어줘. 타이머, 자동제출, 채점, 결과 화면, localStorage 저장까지 포함해줘."
- **P4**: "FR-5 면접 준비 기능을 만들어줘. 카테고리별 질문 목록, 답변 저장, 60~90초 타임어택 모드 포함."
- **P7 (콘텐츠 보강)**: "요구사양서 6.3절 문제은행 목표(수리추론 15문항 x 2세트 등)에 맞춰 '수리추론' 세트 1을 위한 예상문제 15개를 JSON 스키마에 맞게 만들어줘. 정답과 해설도 포함해줘." (문항은 반드시 자체 제작 — 실제 기출 원문 복제 금지 원칙을 프롬프트에 함께 명시)

### 5.3 검토·검증 루틴
- 매 Phase 종료 시 Claude Code에게 "요구사양서 대비 구현 여부 체크리스트"를 작성하게 하고, 8장 체크리스트와 대조
- 콘텐츠(특히 보안 관련 이론)는 배포 전 보호자가 직접 한 번 검수 — 중학생 눈높이에 맞는지, 실습형 공격 코드가 섞이지 않았는지 확인

## 6. Vercel 배포 절차

1. GitHub에 프로젝트 저장소 생성 후 로컬(또는 Claude Code 작업 환경)에서 push
2. [vercel.com](https://vercel.com)에서 GitHub 계정 연동 → 해당 저장소 Import
3. Framework Preset: **Astro**(자동 인식됨), Build Command `astro build`(기본값 그대로 사용 가능)
4. 별도 환경변수 불필요(서버 없음) — Environment Variables 설정 생략
5. 최초 배포 후 `*.vercel.app` 기본 도메인으로 확인, 이후 커스텀 도메인 연결은 선택 사항
6. 이후 `main` 브랜치에 push할 때마다 자동 재배포(CI/CD), PR 생성 시 Preview 배포로 사전 확인 가능
