프로그램이 갑자기 죽거나, 이상한 값을 출력하거나, 만든 사람도 예상 못 한 동작을 할 때가 있어요. 그 원인 중 아주 오래되고 지금도 계속 발견되는 문제가 하나 있습니다. 바로 **정해진 크기의 공간에 그보다 많은 것을 밀어 넣는 실수**예요.

이 챕터는 "그 실수를 어떻게 악용하는가"를 배우는 시간이 아닙니다. **"그 실수를 어떻게 안 하는가"**, 즉 안전하게 코드를 쓰는 습관을 배우는 시간이에요.

> ⚖️ **먼저 짚고 갈 것**
> 허가받지 않은 남의 컴퓨터·서버·프로그램을 대상으로 취약점을 찾거나 시도하는 행위는 **정보통신망법 위반으로 처벌받는 범죄**입니다.
> 실력을 겨루고 싶다면 CTF 대회나 워게임 사이트처럼 **주최 측이 "여기서는 해도 된다"고 명시적으로 허락한 환경**에서만 연습하세요.
> 이 챕터에 실제로 공격에 쓰이는 입력값이나 코드가 없는 것도 같은 이유입니다.

## 핵심 개념 ① 메모리는 칸이 정해진 사물함이에요

프로그램이 변수를 하나 만들면, 컴퓨터는 메모리에 **딱 그만큼의 자리**를 잡아 줍니다.

```c
char name[8];   // 문자 8칸짜리 사물함
```

이건 학교 사물함과 똑같아요. 내 사물함은 폭이 정해져 있고, 바로 옆에는 다른 사람 사물함이 붙어 있죠.

| 주소 | 무엇이 들어 있나 |
|---|---|
| … | 다른 변수 |
| 100 ~ 107 | `name` (8칸) |
| 108 ~ | **바로 옆 다른 데이터** |

여기서 중요한 사실 하나. **C 언어는 "네 사물함은 8칸이야"라고 알려만 주고, 9칸째에 물건을 넣는 걸 막아주지 않아요.**
파이썬이나 자바 같은 언어는 "범위를 벗어났어!"라고 소리치며 멈추지만, C는 조용히 옆 사물함에 물건을 밀어 넣습니다.

이렇게 **정해진 크기(버퍼)를 넘겨서 데이터를 쓰는 것**을 **버퍼 오버플로우(buffer overflow)**라고 불러요. 우리말로는 "넘침" 정도의 뜻이에요.

## 핵심 개념 ② 넘치면 무슨 일이 생기나 — 왜 위험한가

옆 사물함에 물건이 밀려 들어가면 세 단계로 나빠집니다.

**1단계 — 옆 데이터가 망가진다.**
`name` 옆에 `score` 라는 변수가 있었다면, 이름을 길게 넣는 순간 점수가 엉뚱한 값으로 바뀝니다. 사용자는 이름만 입력했는데 성적이 바뀌는 거예요. 코드만 봐서는 원인을 찾기가 정말 어렵습니다.

**2단계 — 프로그램이 죽는다.**
망가진 값이 "다음에 읽을 메모리 위치" 같은 중요한 정보였다면, 프로그램은 있지도 않은 곳을 찾아가다 그대로 멈춥니다. 서버 프로그램이라면 서비스가 중단되죠. 이것만으로도 이미 사고예요.

**3단계 — 프로그램의 통제권을 빼앗긴다.**
함수가 끝나면 "원래 하던 곳으로 돌아가라"는 **돌아갈 주소**가 메모리에 적혀 있어요. 넘친 데이터가 그 주소까지 덮어써 버리면, 프로그램은 **공격자가 정해준 곳으로** 돌아갑니다. 즉 "데이터를 잘못 넣었을 뿐"인 실수가 **남이 내 프로그램을 조종하는 사고**로 커집니다.

여기까지가 개념이에요. **어떤 값을 얼마나 넣어야 그렇게 되는지는 이 챕터에서 다루지 않습니다.** 우리가 알아야 할 건 "그래서 어떻게 막느냐"거든요.

### 같은 결의 실수 — 포맷 스트링

`printf` 는 첫 번째 인자를 **"형식(format)"**으로 해석해요. `%d`, `%s` 같은 기호를 보면 "여기에 값을 끼워 넣으라는 거구나" 하고 동작합니다.

그런데 **사용자가 입력한 문자열을 그 형식 자리에 그대로 넣으면**, 사용자가 쓴 글자가 명령처럼 해석돼요. 사용자는 "데이터"를 준 것뿐인데 프로그램은 "지시"로 읽는 거죠. 그러면 원래 보여줄 생각이 없던 메모리 내용이 화면에 새어 나올 수 있어요.

버퍼 오버플로우와 원인이 똑같습니다. **"데이터와 코드(지시)의 경계가 무너졌다."** 보안 사고의 상당수가 이 한 문장으로 설명돼요.

## 핵심 개념 ③ 어떻게 막나 — 3중 방어

방어는 세 겹으로 생각하면 편해요. 안쪽일수록 우리가 직접 하는 일입니다.

| 겹 | 누가 하나 | 무엇 |
|---|---|---|
| 1겹 (가장 중요) | **개발자인 나** | 길이를 확인하는 함수 쓰기, 경계 검사하기 |
| 2겹 | 컴파일러 | 스택 카나리 |
| 3겹 | 운영체제 / CPU | ASLR, DEP(NX) |

### 1겹 — 내가 지키는 습관 (여기가 본론)

- **길이를 받지 않는 함수를 쓰지 않는다.** `gets()` 는 "몇 글자까지"를 물어보지도 않아요. 위험하다는 지적이 오래 이어진 끝에 2011년에 나온 **C11 표준에서 아예 삭제됐습니다.** 대신 `fgets()` 를 씁니다.
- **복사할 때 목적지 크기를 항상 넘긴다.** `strcpy` 대신 `snprintf`, `memcpy` 는 복사 길이를 직접 계산해서 검사한 뒤에 호출합니다.
- **배열 인덱스는 쓰기 전에 범위를 확인한다.** `if (i >= 0 && i < LEN)` 한 줄이 사고를 막습니다.
- **크기는 `sizeof` 로 구한다.** 숫자 `8` 을 여기저기 적어두면 나중에 배열만 키웠을 때 검사가 옛날 크기로 남아 있게 돼요.
- **사용자 입력은 절대 형식 문자열 자리에 넣지 않는다.** 항상 `printf("%s", 입력)` 처럼 형식은 내가 쓰고 입력은 값으로 넘깁니다.
- **경고를 켜고, 경고를 읽는다.** `-Wall -Wextra` 를 켜면 컴파일러가 위 실수 대부분을 미리 잡아줍니다.

### 2겹 — 스택 카나리 (컴파일러가 해주는 일)

옛날 광부들은 새장에 든 카나리아를 데리고 갱도에 들어갔대요. 유독가스가 새면 새가 먼저 반응하니까요. **스택 카나리**도 똑같은 발상입니다. 중요한 값(돌아갈 주소) 바로 앞에 무작위 숫자를 몰래 놓아두고, 함수가 끝날 때 그 숫자가 그대로인지 확인해요. 넘친 데이터가 지나갔다면 숫자가 바뀌어 있겠죠. 그러면 프로그램은 **일부러 즉시 종료**합니다. 조종당하느니 멈추는 게 낫다는 판단이에요.

### 3겹 — ASLR 과 DEP (운영체제가 해주는 일)

- **ASLR**(주소 공간 배치 무작위화): 프로그램을 실행할 때마다 메모리에 올라가는 위치를 **매번 다르게** 합니다. 목적지 주소를 미리 알 수 없게 만드는 거예요.
- **DEP / NX**(실행 방지): 메모리 영역마다 "여긴 데이터를 두는 곳", "여긴 코드를 실행하는 곳"이라고 꼬리표를 붙이고, **데이터 영역에 있는 것은 실행하지 않습니다.**

두 장치 모두 기본으로 켜져 있어요. 그래서 요즘은 "실수 하나 = 즉시 장악"이 되지는 않습니다. 하지만 **1겹이 뚫린 상태를 전제로 만든 안전망**일 뿐이에요. 안전망을 믿고 줄을 대충 타면 안 되겠죠.

## 예시 — 위험한 코드와 안전한 코드

두 코드를 나란히 보세요. **왼쪽처럼 쓰지 않는 것**이 이 챕터의 결론입니다.

### 예시 1. 문자열 입력받기

```c
// ⚠️ 위험 — 몇 글자가 들어올지 모른 채 8칸에 담는다
#include <stdio.h>

int main(void) {
	char name[8];
	gets(name);              // 길이 제한이 아예 없다
	printf("안녕, %s\n", name);
	return 0;
}
```

```c
// ✅ 안전 — 담을 수 있는 크기를 함수에 알려준다
#include <stdio.h>

int main(void) {
	char name[8];
	if (fgets(name, sizeof(name), stdin) == NULL) {
		return 1;            // 입력 실패도 확인한다
	}
	printf("안녕, %s\n", name);
	return 0;
}
```

`sizeof(name)` 을 넘겼기 때문에, 나중에 배열을 `char name[64]` 로 키워도 검사가 저절로 따라옵니다.

### 예시 2. 문자열 복사하기

```c
// ⚠️ 위험 — src 가 dst 보다 길면 그대로 넘친다
void copy_title(const char *src) {
	char dst[16];
	strcpy(dst, src);
}
```

```c
// ✅ 안전 — 크기를 넘기고, 끝에 널 문자가 붙는 것까지 보장한다
void copy_title(const char *src) {
	char dst[16];
	snprintf(dst, sizeof(dst), "%s", src);
}
```

### 예시 3. 배열에 값 넣기

```c
// ⚠️ 위험 — i 가 범위를 벗어나도 그냥 쓴다
void set_score(int scores[], int i, int value) {
	scores[i] = value;
}
```

```c
// ✅ 안전 — 길이를 함께 받아 경계를 검사한다
int set_score(int scores[], int len, int i, int value) {
	if (i < 0 || i >= len) {
		return -1;             // 거부하고 알린다
	}
	scores[i] = value;
	return 0;
}
```

### 예시 4. 사용자 입력을 출력하기

```c
// ⚠️ 위험 — 사용자가 쓴 글자가 "형식"으로 해석된다
printf(user_input);
```

```c
// ✅ 안전 — 형식은 내가 쓰고, 입력은 값으로만 넘긴다
printf("%s", user_input);
```

차이는 딱 다섯 글자예요. 그런데 이 다섯 글자가 **데이터와 지시의 경계**를 지킵니다.

## 확인 문제

**문제 1.** `char buf[10];` 이 있을 때, 사용자가 20글자를 입력했는데도 프로그램이 아무 검사 없이 그대로 `buf` 에 담았습니다. 이때 벌어질 수 있는 일을 "왜 위험한지"의 관점에서 두 가지 이상 설명해 보세요.

<details>
<summary>정답 확인</summary>

**정답:** ① 버퍼 옆에 있던 다른 변수의 값이 덮여서 프로그램이 엉뚱한 결과를 낸다. ② 중요한 제어 정보(함수가 돌아갈 주소 등)까지 덮이면 프로그램이 비정상 종료되거나, 심하면 프로그램의 실행 흐름을 공격자가 정한 곳으로 돌릴 수 있다.

**해설:** 핵심은 "메모리는 이어져 있고, C는 경계를 대신 지켜주지 않는다"는 점이에요. 그래서 넘친 데이터는 사라지지 않고 **옆 데이터를 덮어씁니다.** 단순한 오작동에서 시작해 서비스 중단, 최악의 경우 통제권 상실까지 이어질 수 있어요.

</details>

**문제 2.** 다음 중 버퍼 오버플로우를 막기 위한 습관으로 **가장 적절하지 않은 것**은 무엇일까요?

1. `gets()` 대신 `fgets()` 를 쓴다
2. 복사 함수에 목적지 배열의 크기를 함께 넘긴다
3. 배열에 값을 쓰기 전에 인덱스가 범위 안인지 확인한다
4. 운영체제에 ASLR 이 켜져 있으니 코드에서는 길이 검사를 생략한다

<details>
<summary>정답 확인</summary>

**정답:** 4번

**해설:** ASLR·DEP·스택 카나리는 **마지막 안전망**이지 첫 번째 방어선이 아니에요. 이 장치들은 "실수가 이미 일어났을 때 피해를 줄이는" 역할을 합니다. 실수 자체를 없애는 건 1겹, 즉 길이를 확인하는 코딩 습관이에요. 안전망을 이유로 안전벨트를 풀면 안 되겠죠.

</details>

**문제 3.** 친구가 "학교 홈페이지에 버퍼 오버플로우가 있는지 직접 넣어보며 확인해 보자"고 제안했어요. 어떻게 답하는 것이 옳을까요?

<details>
<summary>정답 확인</summary>

**정답:** 거절해야 합니다. 허가 없이 남의 시스템을 대상으로 취약점을 시도하는 것은 **정보통신망법 위반인 범죄**예요. 연습은 CTF 대회나 워게임처럼 **주최 측이 허용한 환경**에서, 또는 **내가 직접 만든 프로그램**을 대상으로만 합니다.

**해설:** "테스트해 보려던 것뿐"이라는 의도는 면책 사유가 되지 않아요. 보안을 공부하는 사람에게 가장 먼저 필요한 자질은 기술이 아니라 **허락받은 범위 안에서만 움직이는 태도**입니다. 만약 우연히 문제를 발견했다면, 시도하지 말고 관리자나 학교에 알리는 것이 올바른 순서예요.

</details>

## 요약

- 메모리는 칸이 정해진 사물함이고, C 언어는 **경계를 대신 지켜주지 않는다.** 넘친 데이터는 옆 데이터를 덮어쓴다.
- 넘침의 피해는 ① 값 오염 → ② 프로그램 종료 → ③ 실행 흐름 탈취 순으로 커진다. 포맷 스트링 문제도 **데이터와 지시의 경계가 무너진** 같은 결의 실수다.
- 1겹 방어(가장 중요)는 **내 습관**이다. `gets()` 금지, 크기를 넘기는 `fgets`·`snprintf`, 인덱스 경계 검사, `sizeof` 사용, 형식 문자열에 사용자 입력 넣지 않기, 컴파일러 경고 켜기.
- 2·3겹인 스택 카나리·ASLR·DEP 는 **실수가 났을 때를 대비한 안전망**이지 면허증이 아니다.
- 허가 없는 시도는 범죄다. 연습은 CTF·워게임 등 **허락된 환경**에서만 한다.
