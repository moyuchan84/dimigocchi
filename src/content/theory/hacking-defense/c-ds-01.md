## 핵심 개념 1 — 메모리는 번호가 붙은 사물함

학교 복도에 사물함이 쭉 늘어서 있다고 생각해 보세요. 사물함마다 **번호**가 붙어 있고, 그 안에는 **물건**이 들어 있어요. 번호는 절대 바뀌지 않고, 안의 물건은 바꿔 넣을 수 있죠.

컴퓨터의 **메모리(RAM)** 가 딱 이래요.

```
번호:  1000   1001   1002   1003   1004   1005  ...
      ┌────┐┌────┐┌────┐┌────┐┌────┐┌────┐
      │ 65 ││  0 ││  0 ││  0 ││ 72 ││  0 │
      └────┘└────┘└────┘└────┘└────┘└────┘
```

- 사물함 한 칸 = **1바이트(byte)**
- 사물함 번호 = **주소(address)**
- 사물함 안의 내용물 = **값(value)**

여기서 중요한 사실 하나. 메모리에는 "여기부터 여기까지가 성적이고, 저기는 이름"이라는 이름표가 붙어 있지 않아요. **전부 그냥 숫자**예요. 그래서 프로그래머가 "이 칸부터 4칸은 정수로 읽어라"라고 정해 줘야 하는데, 그 약속이 바로 **자료형**입니다.

C언어는 이 사물함을 프로그래머가 직접 관리하는 언어예요. 파이썬 같은 언어는 알아서 정리해 주지만, C는 "몇 칸 쓸지, 언제 비울지"를 사람이 정해요. 불편한 대신 컴퓨터가 실제로 어떻게 동작하는지가 그대로 보여요. 운영체제, 서버 프로그램, 그리고 보안 취약점 대부분이 이 층위에서 생깁니다.

## 핵심 개념 2 — 변수와 자료형, 그리고 크기

**변수**는 사물함 한 칸(또는 여러 칸)에 **이름을 붙인 것**이에요. `1004번 사물함` 대신 `score` 라고 부르는 거죠.

```c
int score = 95;
```

이 한 줄이 하는 일은 세 가지예요.

1. 메모리에서 **연속된 4칸**을 빌린다 (`int` 라서 4바이트)
2. 그 자리에 `score` 라는 이름을 붙인다
3. 거기에 95를 써 넣는다

자료형마다 빌리는 칸 수가 달라요. (아래는 오늘날 PC·서버에서 가장 흔한 크기예요. C 표준은 정확한 크기를 못 박지 않아서 환경에 따라 달라질 수 있어요.)

| 자료형 | 담는 것 | 크기 | 표현 범위(대략) |
| --- | --- | --- | --- |
| `char` | 문자 하나 | 1바이트 | -128 ~ 127 |
| `short` | 작은 정수 | 2바이트 | -32,768 ~ 32,767 |
| `int` | 정수 | 4바이트 | 약 -21억 ~ 21억 |
| `long long` | 큰 정수 | 8바이트 | 약 -922경 ~ 922경 |
| `float` | 실수 | 4바이트 | 소수점 아래 약 7자리 정밀도 |
| `double` | 정밀한 실수 | 8바이트 | 소수점 아래 약 15자리 정밀도 |

크기는 `sizeof` 연산자로 직접 확인할 수 있어요.

```c
#include <stdio.h>

int main(void) {
	printf("char      : %zu 바이트\n", sizeof(char));
	printf("int       : %zu 바이트\n", sizeof(int));
	printf("float     : %zu 바이트\n", sizeof(float));
	printf("double    : %zu 바이트\n", sizeof(double));
	return 0;
}
```

```
char      : 1 바이트
int       : 4 바이트
float     : 4 바이트
double    : 8 바이트
```

### 크기가 왜 중요할까

1바이트는 8비트니까 `char` 는 2⁸ = 256가지만 표현할 수 있어요. `int` 는 4바이트 = 32비트라서 2³² ≈ 43억 가지, 음수까지 반씩 나눠 쓰니 약 -21억 ~ 21억이에요.

그럼 21억을 넘기면 어떻게 될까요?

```c
int big = 2147483647;   // int 가 담을 수 있는 최댓값
big = big + 1;
printf("%d\n", big);
```

```
-2147483648
```

가장 큰 수에 1을 더했는데 갑자기 가장 작은 음수가 됐어요. 자동차 계기판이 999999를 넘으면 000000으로 돌아가는 것과 같아요. 이걸 **오버플로(overflow)** 라고 해요.

이게 왜 보안 이야기냐면, 실제 프로그램에서 "결제 금액", "남은 좌석 수", "복사할 데이터 길이" 같은 걸 계산하다가 오버플로가 나면 프로그램의 판단이 통째로 뒤집히기 때문이에요. 그래서 안전한 코드는 **더하기 전에 넘칠지 먼저 검사**해요. 자료형의 크기를 아는 건 그 검사를 하기 위한 출발점입니다.

## 핵심 개념 3 — 포인터, 주소를 담는 변수

포인터는 C에서 가장 어려운 부분으로 꼽히지만, 사물함 비유를 계속 쓰면 그렇게 어렵지 않아요.

### 1단계: 값과 주소는 다르다

```c
int score = 95;
```

여기서 `score` 라는 이름이 가리키는 것은 두 가지예요.

- **값**: 95
- **주소**: 이 변수가 놓인 사물함 번호 (예: 1004)

주소를 알고 싶으면 이름 앞에 `&` 를 붙여요. `&score` = "score의 주소".

```c
int score = 95;
printf("값   : %d\n", score);
printf("주소 : %p\n", (void *)&score);
```

```
값   : 95
주소 : 0x7ffd3c1a4f2c
```

주소는 보통 16진수로 나오고, 실행할 때마다 값이 달라요. 정확한 숫자는 중요하지 않아요. **"변수마다 자기 자리 번호가 있다"** 는 사실만 잡으면 돼요.

### 2단계: 주소를 저장하는 변수가 포인터

주소도 결국 숫자니까, 그걸 담아 두는 변수를 만들 수 있어요. 그게 **포인터**예요.

```c
int score = 95;
int *p = &score;   // p 는 score 의 주소를 담는다
```

`int *p` 는 "p는 int가 있는 자리의 주소를 담는 변수"라는 뜻이에요. 그림으로 보면 이래요.

```
        p                        score
  ┌───────────┐            ┌───────────┐
  │   1004    │ ─────────▶ │    95     │
  └───────────┘            └───────────┘
   주소 2000                 주소 1004
```

`p` 는 사물함 열쇠고리에 붙은 **번호표**예요. 번호표 자체에는 95가 없어요. "95는 1004번 사물함에 있다"는 정보만 있죠.

### 3단계: 번호표를 따라가기

번호표를 보고 실제 사물함을 열어 보는 걸 **역참조**라고 하고, `*` 를 붙여서 해요.

```c
int score = 95;
int *p = &score;

printf("%d\n", *p);   // p가 가리키는 곳의 값 → 95

*p = 100;             // p가 가리키는 곳에 100을 써 넣는다
printf("%d\n", score); // 100  ← score 가 바뀌었다!
```

마지막 줄이 포인터의 핵심이에요. `score` 를 직접 건드리지 않았는데 값이 바뀌었어요. 번호표를 따라가서 그 사물함의 내용물을 갈아 끼웠으니까요.

정리하면 이렇게 짝을 이뤄요.

| 기호 | 읽는 법 | 하는 일 |
| --- | --- | --- |
| `&x` | x의 주소 | 값 → 주소 |
| `*p` | p가 가리키는 값 | 주소 → 값 |

### 포인터를 왜 쓰나요

가장 흔한 이유는 **함수 안에서 바깥 변수를 바꾸기 위해서**예요. C에서 함수에 값을 넘기면 사본이 전달돼요.

```c
void addTen(int n) {
	n = n + 10;        // 사본만 바뀐다
}

void addTenReal(int *n) {
	*n = *n + 10;      // 원본이 있는 자리를 직접 고친다
}

int main(void) {
	int a = 5, b = 5;
	addTen(a);
	addTenReal(&b);
	printf("a=%d, b=%d\n", a, b);   // a=5, b=15
	return 0;
}
```

`a` 는 그대로고 `b` 만 바뀌었죠. 사본을 받으면 원본에 영향이 없고, 주소를 받으면 원본을 고칠 수 있어요.

### 포인터가 위험한 이유

포인터는 강력한 만큼 위험해요. 잘못된 번호표를 따라가면 **엉뚱한 사물함**을 열게 되니까요.

- 아무 데도 가리키지 않는 포인터(`NULL`)를 역참조하면 프로그램이 그 자리에서 죽어요
- 이미 반납한 사물함의 번호표를 계속 들고 있다가 열면, 그 사이 다른 사람 물건이 들어와 있어요
- 빌린 칸 수보다 많이 써 넣으면 **옆 사물함까지 침범**해요

세 번째가 그 유명한 **버퍼 오버플로**예요. 아직 자세히 다루지 않지만, "메모리는 칸이 정해져 있고 넘치면 옆을 덮어쓴다"는 감각만 지금 잡아 두세요. 다음 챕터(안전한 코딩 습관)에서 이어집니다.

## 핵심 개념 4 — 배열: 사물함을 줄줄이 빌리기

같은 종류의 자료 여러 개를 다룰 땐 배열을 써요.

```c
int scores[5] = {90, 85, 77, 100, 68};
```

배열의 핵심 성질은 **메모리에 빈틈없이 이어서 놓인다**는 거예요.

```
 인덱스:    [0]    [1]    [2]    [3]    [4]
          ┌────┐┌────┐┌────┐┌────┐┌────┐
          │ 90 ││ 85 ││ 77 ││100 ││ 68 │
          └────┘└────┘└────┘└────┘└────┘
 주소:     1000  1004  1008  1012  1016
           └─4바이트씩 정확히 떨어져 있음─┘
```

그래서 `scores[3]` 을 찾을 때 컴퓨터는 앞에서부터 세지 않아요. **시작 주소 + 3 × 4바이트** 를 한 번에 계산해서 바로 갑니다. 몇 번째든 걸리는 시간이 같아요. 배열이 빠른 이유예요.

인덱스가 **0부터 시작**하는 것도 이 계산 때문이에요. 첫 번째 칸은 시작 주소에서 0칸 떨어져 있으니까요.

```c
int scores[5] = {90, 85, 77, 100, 68};
int sum = 0;

for (int i = 0; i < 5; i++) {
	sum += scores[i];
}
printf("합계 %d, 평균 %.1f\n", sum, sum / 5.0);
```

```
합계 420, 평균 84.0
```

주의할 점 하나. C는 **배열 범위를 벗어나도 막아 주지 않아요.** `scores[7]` 이라고 쓰면 그냥 옆 사물함을 읽어 옵니다. 오류 메시지도 없이 이상한 값이 나오죠. 반복문 조건을 `i < 5` 로 정확히 맞추는 습관이 곧 보안 습관이에요.

## 핵심 개념 5 — 스택과 큐

배열은 "몇 번째"로 접근하는 구조였어요. 반대로 **넣고 빼는 순서에 규칙**을 둔 자료구조도 있어요. 대표가 스택과 큐예요.

### 스택(stack) — 나중에 넣은 걸 먼저 꺼낸다

프링글스 통을 떠올리세요. 위로만 넣고, 위에서만 꺼내요. 맨 마지막에 넣은 게 가장 먼저 나오죠. 이걸 **LIFO**(Last In First Out)라고 해요.

```
push(1)   push(2)   push(3)    pop() → 3   pop() → 2
                      ┌───┐
            ┌───┐     │ 3 │      ┌───┐
  ┌───┐     │ 2 │     │ 2 │      │ 2 │      ┌───┐
  │ 1 │     │ 1 │     │ 1 │      │ 1 │      │ 1 │
  └───┘     └───┘     └───┘      └───┘      └───┘
```

- `push` = 위에 쌓기
- `pop` = 맨 위 꺼내기
- `top`(또는 `peek`) = 맨 위를 꺼내지 않고 보기만 하기

배열로 만들면 "지금 몇 개 쌓였는지"를 세는 변수 하나만 있으면 돼요.

```c
int stack[100];
int top = 0;            // 다음에 넣을 자리

void push(int x) {
	stack[top] = x;
	top++;
}

int pop(void) {
	top--;
	return stack[top];
}
```

스택은 우리가 매일 쓰고 있어요. 브라우저의 뒤로 가기, 편집기의 실행 취소(Ctrl+Z)가 전부 스택이에요. 가장 최근 것부터 되돌리니까요. 그리고 프로그램이 함수를 호출할 때 "돌아갈 자리"를 기록해 두는 메모리 영역도 **콜 스택**이라고 불러요. 이름 그대로 스택 구조입니다.

### 큐(queue) — 먼저 넣은 걸 먼저 꺼낸다

급식 줄을 떠올리세요. 먼저 선 사람이 먼저 받아요. 뒤로 들어와서 앞으로 나가죠. 이걸 **FIFO**(First In First Out)라고 해요.

```
enqueue: 뒤로 들어옴 →  [ 1 ][ 2 ][ 3 ]  → dequeue: 앞으로 나감
                        앞            뒤
```

- `enqueue` = 뒤에 줄 세우기
- `dequeue` = 앞에서 내보내기

```c
int queue[100];
int front = 0;   // 나갈 자리
int rear = 0;    // 들어올 자리

void enqueue(int x) {
	queue[rear] = x;
	rear++;
}

int dequeue(void) {
	int x = queue[front];
	front++;
	return x;
}
```

큐도 주변에 흔해요. 프린터가 인쇄 요청을 받은 순서대로 처리하는 것, 서버가 동시에 들어온 접속 요청을 순서대로 처리하는 것이 전부 큐예요.

### 한눈에 비교

| | 스택 | 큐 |
| --- | --- | --- |
| 규칙 | LIFO (나중에 넣은 게 먼저) | FIFO (먼저 넣은 게 먼저) |
| 넣기 / 빼기 | push / pop | enqueue / dequeue |
| 비유 | 프링글스 통, 접시 쌓기 | 급식 줄, 매표소 줄 |
| 쓰임 | 뒤로 가기, 실행 취소, 함수 호출 기록 | 인쇄 대기열, 요청 처리 순서 |

둘 다 **넣는 곳과 빼는 곳을 제한**해서 순서를 보장하는 게 핵심이에요. 어떤 순서로 처리해야 하는 문제인지 파악하면 어느 쪽을 쓸지 바로 정해집니다.

<details>
<summary>정답 확인</summary>

**정답:** 2024번. 이유는 원소가 메모리에 연속으로 놓여 있어서 **시작 주소 + 인덱스 × 자료형 크기**로 위치를 바로 계산할 수 있기 때문이에요.

**문제 2.** 아래 코드의 출력은 무엇일까요?

```c
int a = 7;
int *p = &a;
*p = *p * 2;
printf("%d\n", a);
```

<details>
<summary>정답 확인</summary>

**정답:** `14`

**해설:** 한 줄씩 따라가 봐요.

1. `int a = 7;` → 어떤 사물함(가령 1000번)에 7을 넣고 `a` 라는 이름을 붙여요.
2. `int *p = &a;` → `p` 에 a의 주소(1000)를 저장해요. 번호표를 받은 거예요.
3. `*p = *p * 2;` → 오른쪽 `*p` 는 1000번 칸의 값 7. 2를 곱해 14. 왼쪽 `*p` 는 "1000번 칸에 써 넣어라"는 뜻이라 14가 저장돼요.
4. `a` 와 `*p` 는 **같은 사물함**이므로 `a` 도 14가 됩니다.

`a` 를 직접 쓰지 않았는데 값이 바뀌는 것 — 이게 포인터의 힘이자 조심해야 할 이유예요.

</details>

**문제 3.** 다음 두 상황에 스택과 큐 중 어느 것이 어울리는지 고르고 이유를 말해 보세요. (1) 웹 브라우저에서 뒤로 가기 버튼을 눌렀을 때 방문 기록을 되돌리기 (2) 학교 프린터가 여러 학생의 인쇄 요청을 처리하기

<details>
<summary>정답 확인</summary>

**정답:** (1) 스택 (2) 큐

**해설:**

(1) 뒤로 가기는 **가장 최근에 본 페이지**부터 되돌아가야 해요. A → B → C 순으로 방문했다면 뒤로 가기를 눌렀을 때 C 다음에 B로 가야 자연스럽죠. 마지막에 넣은 게 먼저 나오는 LIFO, 즉 스택이에요.

(2) 인쇄는 **먼저 요청한 사람**이 먼저 받아야 공평해요. 나중에 요청한 사람이 먼저 나오면 앞사람은 계속 밀려서 영영 못 받을 수도 있어요. 먼저 넣은 게 먼저 나오는 FIFO, 즉 큐입니다.

판단 기준은 간단해요. **"최근 것부터"면 스택, "순서대로 공평하게"면 큐.**

</details>

## 요약

- 메모리는 **번호(주소)가 붙은 1바이트짜리 사물함**의 줄이에요. 변수는 그중 몇 칸을 빌려 이름을 붙인 것이고, 몇 칸을 빌릴지 정하는 게 **자료형**이에요.
- `char` 1바이트, `int` 4바이트, `double` 8바이트가 흔한 크기예요. 크기에는 한계가 있어서 범위를 넘기면 **오버플로**로 값이 엉뚱하게 뒤집혀요 — 계산 전에 검사하는 습관이 보안의 시작이에요.
- **포인터는 주소를 담는 변수**예요. `&x` 는 값에서 주소로, `*p` 는 주소에서 값으로 가는 기호. 번호표를 따라가면 원본을 직접 고칠 수 있어서 강력하지만, 잘못된 번호표는 프로그램을 무너뜨려요.
- **배열은 메모리에 연속으로 놓여** 있어서 `시작 주소 + 인덱스 × 크기` 로 어디든 한 번에 갑니다. 대신 C는 범위를 벗어나도 막아 주지 않으니 반복문 조건을 정확히 맞춰야 해요.
- **스택은 LIFO**(push/pop — 뒤로 가기, 실행 취소), **큐는 FIFO**(enqueue/dequeue — 인쇄 대기열, 요청 처리). 넣고 빼는 곳을 제한해 순서를 보장하는 자료구조예요.
