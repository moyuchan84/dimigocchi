## 시작하기 전에 — 이 챕터의 목표

"리버싱"이라는 말을 들으면 게임 핵이나 프로그램 크랙 같은 걸 떠올리기 쉬워요. 하지만 그건 리버싱이라는 기술의 **불법적인 오용**이고, 이 챕터에서 다룰 내용이 아니에요.

이 챕터의 목표는 **"프로그램이 만들어져서 실행되기까지 무슨 일이 벌어지는가"** 를 이해하는 거예요. 그 과정을 알면 백신이 악성코드를 어떻게 분석하는지, 보안 담당자가 왜 이 기술을 배우는지가 자연스럽게 보여요.

먼저 선을 하나 그어둘게요.

> **다른 사람이 만든 프로그램의 보호 장치를 우회하거나, 유료 소프트웨어의 라이선스 확인을 무력화하는 방법은 이 챕터에서 다루지 않아요.**
> 그건 저작권법 위반이고, 대상이 남의 서버라면 「정보통신망 이용촉진 및 정보보호 등에 관한 법률」 위반이기도 해요. 허락 없이 남의 시스템이나 프로그램을 분석·조작하는 건 명백한 불법입니다.
> 연습은 **CTF 대회**나 **워게임 사이트**처럼 주최자가 "이 파일을 분석해 보세요"라고 문제로 내놓은 환경, 또는 **자기가 직접 만든 프로그램**을 대상으로만 하세요.

## 핵심 개념 1 — 내가 쓴 코드가 실행되기까지

우리가 C언어로 쓴 코드는 사람이 읽으라고 만든 글이에요. 컴퓨터의 CPU는 그 글을 읽지 못해요. 그래서 **번역**이 필요해요.

```
소스 코드  →  [컴파일]  →  목적 파일  →  [링크]  →  실행 파일  →  [실행]  →  메모리 위의 프로세스
 (사람용)                   (기계어 조각)            (완성품)                    (움직이는 상태)
```

한 단계씩 볼게요.

### ① 소스 코드

사람이 쓴 글이에요. `hello.c` 같은 파일이죠. 텍스트라서 메모장으로 열어도 읽혀요.

```c
#include <stdio.h>

int main(void) {
	printf("안녕하세요\n");
	return 0;
}
```

### ② 컴파일 — 사람의 말을 기계의 말로

컴파일러가 이 글을 **기계어**로 번역해요. 기계어는 CPU가 직접 이해하는 명령의 목록이고, 실제로는 그냥 **숫자의 나열**이에요.

이 단계에서 **아주 중요한 일이 벌어져요. 정보가 사라져요.**

- 변수 이름 `score`, `playerName` 같은 건 CPU에게 필요 없어요. "메모리 몇 번째 칸"이면 충분하니까요. 그래서 **이름이 대부분 지워져요.**
- `// 여기는 점수 계산` 같은 주석은 애초에 번역 대상이 아니에요. **통째로 사라져요.**
- `if`, `for` 같은 구조도 "조건을 비교하고, 맞으면 저쪽으로 뛰어라" 같은 더 원시적인 형태로 풀어져요.

### ③ 링크 — 조각을 하나로 붙이기

`printf` 같은 함수는 내가 만든 게 아니라 이미 만들어진 라이브러리에 있어요. 링커가 내 코드 조각과 필요한 라이브러리 조각을 이어 붙여서 **하나의 실행 파일**을 완성해요. 윈도우에서는 `.exe`, 리눅스에서는 확장자 없는 파일인 경우가 많아요.

### ④ 실행 — 메모리에 올라가 살아 움직이기

실행 파일을 더블클릭하면, 운영체제가 그 파일을 **메모리(RAM)에 올려요.** 그리고 CPU가 첫 명령부터 순서대로 읽으며 실행해요. 이 "움직이는 상태"를 **프로세스**라고 불러요.

여기서 기억할 점: **파일 상태와 실행 상태는 다르다**는 거예요. 파일은 가만히 있는 설계도이고, 프로세스는 그 설계도대로 실제로 돌아가는 기계예요. 그래서 분석 방법도 둘로 나뉘어요. (뒤에서 다시 나와요.)

## 핵심 개념 2 — 기계어와 어셈블리

### 기계어는 읽기가 너무 어렵다

기계어를 그대로 열어보면 이런 숫자들이 끝없이 나와요.

```
55 48 89 e5 48 83 ec 10 ...
```

이 숫자 하나하나가 CPU에게 내리는 명령이에요. 사람이 이걸 보고 프로그램의 동작을 파악하는 건 사실상 불가능하죠.

### 어셈블리 = 기계어에 이름표를 붙인 것

그래서 **어셈블리 언어**가 있어요. 기계어 명령 하나하나에 사람이 읽을 수 있는 짧은 이름을 붙인 표기법이에요.

| 어셈블리 표기 | 대충 이런 뜻 |
|---|---|
| `mov` | 값을 옮겨라 |
| `add` | 더해라 |
| `cmp` | 두 값을 비교해라 |
| `jmp` | 저쪽으로 건너뛰어라 |
| `call` | 함수를 불러라 |
| `ret` | 부른 곳으로 돌아가라 |

어셈블리는 **기계어와 거의 1:1로 대응**해요. C언어의 한 줄이 기계어 여러 개로 번역되는 것과 달리, 어셈블리 한 줄은 기계어 명령 하나예요. 그래서 실행 파일을 어셈블리로 되돌리는 건 (거의) 기계적으로 가능해요. 이 작업을 **디스어셈블(disassemble)** 이라고 해요.

여기서 리버싱의 본질이 드러나요.

> **기계어 → 어셈블리는 거의 자동으로 되돌릴 수 있다.**
> **하지만 어셈블리 → 원래 소스 코드는 완전히 되돌릴 수 없다.**
> 컴파일 과정에서 변수 이름과 주석이 사라졌기 때문이다.

번역에 비유하면 이래요. 한국어 문장을 다른 언어로 번역했다가 다시 한국어로 옮기면, 뜻은 대충 통해도 원래 문장 그대로는 안 나오죠. 리버싱도 마찬가지예요. **동작은 파악할 수 있지만 원본 소스는 복원되지 않아요.** 그래서 분석가는 흐름을 읽고 자기 나름대로 이름을 붙여가며 **추측하고 재구성**해요. 이게 리버싱이 어렵고, 동시에 재미있는 이유예요.

## 핵심 개념 3 — 리버스 엔지니어링이란 무엇인가

**리버스 엔지니어링(역공학)** 은 완성된 결과물을 뜯어보며 그 구조와 동작 원리를 알아내는 일이에요. 소프트웨어만의 개념도 아니에요. 자동차 회사가 경쟁사 차를 분해해 보거나, 고장 난 기계를 뜯어 원리를 파악하는 것도 같은 개념이에요.

소프트웨어에서는 **소스 코드 없이 실행 파일만 가지고 그 프로그램이 무슨 일을 하는지 알아내는 것**을 말해요.

### 분석 방법은 크게 두 가지

| 구분 | 정적 분석 | 동적 분석 |
|---|---|---|
| 무엇을 보나 | 실행하지 않고 **파일 자체**를 본다 | **실제로 실행시키면서** 관찰한다 |
| 비유 | 설계도를 펼쳐놓고 읽기 | 기계를 켜놓고 어디가 움직이는지 보기 |
| 대표 도구 | 디스어셈블러 (예: Ghidra, IDA) | 디버거, 샌드박스 |
| 장점 | 위험한 코드를 실행하지 않아 안전 | 실제 동작(통신, 파일 생성)을 볼 수 있음 |
| 주의점 | 숨겨진 동작은 놓칠 수 있음 | 반드시 **격리된 환경**에서 해야 함 |

동적 분석에서 "격리된 환경"이 특히 중요해요. 악성코드를 분석한다면서 자기 컴퓨터에서 그냥 실행하면 본인이 감염돼요. 그래서 분석가는 **가상 머신이나 샌드박스** — 바깥과 차단된 별도의 컴퓨터 환경 — 안에서만 실행해요.

## 핵심 개념 4 — 왜 보안 담당자가 이걸 배우는가

리버싱은 **합법적이고 꼭 필요한 용도**가 분명한 기술이에요.

**① 악성코드 분석**

새로운 악성코드가 발견되면, 분석가가 그걸 뜯어봐요. 무슨 파일을 건드리는지, 어디로 통신하는지, 어떤 조건에서 동작하는지를 알아내야 **백신이 탐지 규칙을 만들고, 피해 확산을 막을 수 있어요.** 악성코드는 당연히 소스 코드를 안 주니까, 실행 파일만 가지고 알아내야 해요. 리버싱 없이는 불가능한 일이에요.

**② 취약점 진단과 패치 검증**

우리 회사가 쓰는 프로그램에 위험한 버그가 있는지 확인해야 할 때가 있어요. 소스 코드를 받을 수 없는 상용 프로그램이라면 실행 파일을 분석하는 수밖에 없죠. 보안 패치가 나왔을 때 **정말로 그 문제가 고쳐졌는지 확인**하는 데도 쓰여요.

**③ 호환성 확보와 기술 이해**

문서가 사라진 오래된 시스템, 개발사가 없어진 프로그램의 데이터 형식을 알아내 이어서 쓰는 경우예요. 「저작권법」에도 **호환성 확보를 위한 프로그램코드역분석**을 일정 조건에서 허용하는 조항(제101조의4)이 있어요. 다만 "호환에 필요한 부분에 한하여"처럼 조건이 붙어 있다는 점이 중요해요. **호환성을 핑계로 아무거나 뜯어봐도 된다는 뜻이 아니에요.**

**④ CTF와 학습**

CTF(Capture The Flag) 대회에는 리버싱 문제 분야가 거의 항상 있어요. 주최 측이 만든 프로그램을 분석해 숨겨진 답을 찾아내는 형식이죠. **합법적으로 제공된 문제 파일**을 대상으로 하니 마음껏 연습할 수 있어요.

### 그런데 왜 "방어하는 사람"이 공격자의 기술을 배울까

간단해요. **상대가 무엇을 어떻게 하는지 모르면 막을 수 없기 때문**이에요.

의사가 병을 고치려면 병이 어떻게 퍼지는지 알아야 하잖아요. 그렇다고 의사가 병을 퍼뜨리는 사람은 아니죠. 보안도 똑같아요. 공격 기법을 이해하는 목적은 **탐지하고 차단하기 위해서**예요.

그래서 기술 자체보다 **그 기술을 어디에 쓰느냐**가 훨씬 중요해요. 같은 디스어셈블러로 어떤 사람은 악성코드를 분석해 사람들을 보호하고, 어떤 사람은 남의 소프트웨어를 불법 복제해요. 도구는 같지만 한쪽은 직업이고 한쪽은 범죄예요.

## 핵심 개념 5 — 법과 약관: 어디까지가 허용될까

이 부분은 꼭 짚고 가야 해요.

**① 소프트웨어는 저작물이다**

프로그램은 「저작권법」이 보호하는 저작물이에요. 다른 사람의 프로그램을 마음대로 뜯어보고 고쳐서 배포하는 건 저작권 침해가 될 수 있어요. 특히 **보호 장치를 무력화하는 것**은 별도로 금지돼 있어요.

**② 이용약관(EULA)에 명시된 경우가 많다**

프로그램을 설치할 때 뜨는 긴 약관 — 그 안에 "역분석·디컴파일을 금지한다"는 조항이 들어 있는 경우가 흔해요. 아무도 안 읽지만, 동의 버튼을 누른 이상 그 조건에 동의한 거예요.

**③ 남의 시스템이 대상이면 형사 문제가 된다**

허락 없이 남의 서버나 기기에 접근해 분석하는 건 정보통신망법 위반이에요. "취약점을 알려주려고 그랬다"는 선의도 **사전 허락이 없으면** 면책되지 않아요. 그래서 보안 업계에는 기업이 공식적으로 "우리 서비스를 테스트해도 좋다"고 허용하는 **버그 바운티** 제도가 있어요. 범위와 규칙을 정해놓고 그 안에서만 하는 거죠.

### 그래서 안전하게 배우는 방법

- **내가 직접 만든 프로그램**을 컴파일해서 뜯어보기. 가장 좋은 출발점이에요. 소스를 아니까 어셈블리와 대조하며 배울 수 있어요.
- **CTF 리버싱 문제** 풀기. 분석하라고 만들어 배포한 파일이에요.
- **워게임 사이트**의 리버싱 단계. 단계별로 난이도가 올라가 학습에 좋아요.
- **오픈소스 프로그램**을 컴파일해 보고 결과물을 관찰하기.

이 네 가지 안에서만 놀아도 배울 게 넘칠 만큼 많아요. 굳이 선을 넘을 이유가 없어요.

## 확인 문제

**문제 1.** 컴파일된 실행 파일을 디스어셈블하면 어셈블리 코드를 볼 수 있어요. 그런데 왜 원래의 C 소스 코드를 그대로 되살릴 수는 없을까요?

<details>
<summary>정답 확인</summary>

**정답:** 컴파일 과정에서 **변수 이름, 함수 이름, 주석** 같은 "사람을 위한 정보"가 사라지기 때문이에요.

**해설:** CPU는 `score`라는 이름이 필요 없고 "메모리 몇 번째 칸"이면 충분해요. 주석은 아예 번역 대상이 아니고요. `if`나 `for` 같은 구조도 비교와 점프라는 더 원시적인 형태로 풀어져요.

그래서 기계어 → 어셈블리는 거의 1:1로 되돌릴 수 있지만, 어셈블리 → 원본 소스는 복원이 아니라 **추측과 재구성**이 돼요. 분석가는 흐름을 읽으며 스스로 이름을 붙여가며 의미를 파악해요.

</details>

**문제 2.** 새로 발견된 악성코드 파일을 분석해야 해요. 정적 분석과 동적 분석 중 무엇부터 하는 게 안전할까요? 동적 분석을 한다면 반드시 지켜야 할 조건은 무엇일까요?

<details>
<summary>정답 확인</summary>

**정답:** **정적 분석**부터 하는 것이 안전해요. 동적 분석을 한다면 반드시 **가상 머신·샌드박스 같은 격리된 환경**에서 해야 해요.

**해설:** 정적 분석은 파일을 **실행하지 않고** 구조만 살펴보는 방식이라 분석하는 컴퓨터가 감염될 위험이 없어요. 먼저 정적으로 대략의 성격을 파악한 뒤, 숨겨진 동작을 확인해야 할 때 동적 분석으로 넘어가요.

동적 분석은 실제로 실행시키므로 통신·파일 생성 같은 진짜 동작을 볼 수 있지만, 그만큼 위험해요. 바깥 네트워크와 차단된 격리 환경에서만 실행하고, 분석이 끝나면 그 환경을 통째로 되돌리는 것이 기본이에요.

</details>

**문제 3.** 친구가 "유료 프로그램의 라이선스 확인 부분을 찾아서 없애는 법을 알려달라. 리버싱 공부잖아"라고 해요. 어떻게 답하는 게 맞을까요?

<details>
<summary>정답 확인</summary>

**정답:** 거절해야 해요. 그건 학습이 아니라 **저작권법 위반**이고, 대부분 이용약관 위반이기도 해요.

**해설:** 소프트웨어는 저작권법이 보호하는 저작물이고, 보호 장치를 무력화하는 행위는 별도로 금지돼 있어요. 설치 시 동의한 이용약관에 역분석 금지 조항이 들어 있는 경우도 흔하고요. "공부 목적"이라는 이유는 면책 사유가 되지 않아요.

같은 기술을 합법적으로 익힐 방법은 얼마든지 있어요. **내가 직접 만든 프로그램**을 컴파일해 뜯어보기, **CTF 리버싱 문제** 풀기, **워게임 사이트** 이용하기, 오픈소스 프로그램의 빌드 결과 관찰하기 등이에요. 보안을 직업으로 삼으려면 기술만큼이나 **선을 지키는 태도**가 평가받는다는 점도 기억하세요.

</details>

## 요약

- 프로그램은 **소스 코드 → 컴파일 → 링크 → 실행 파일 → 메모리 위의 프로세스** 순으로 만들어지고 실행돼요. 컴파일 단계에서 변수 이름과 주석 같은 사람을 위한 정보가 사라져요.
- **기계어**는 CPU가 이해하는 숫자 명령이고, **어셈블리**는 그 명령에 사람이 읽을 이름을 붙인 표기예요. 기계어 ↔ 어셈블리는 거의 1:1이라 되돌릴 수 있지만, **원본 소스 코드는 복원되지 않아요.**
- **리버스 엔지니어링**은 소스 없이 실행 파일만으로 동작을 알아내는 일이에요. 실행하지 않는 **정적 분석**과 격리 환경에서 실행하는 **동적 분석**으로 나뉘어요.
- 합법적 용도가 분명해요. **악성코드 분석, 취약점 진단·패치 검증, 호환성 확보, CTF 학습.** 방어하는 사람이 배우는 이유는 **상대를 이해해야 막을 수 있기 때문**이에요.
- 소프트웨어는 저작물이고 이용약관에 역분석 금지 조항이 있는 경우가 많아요. 남의 시스템을 허락 없이 분석하는 건 정보통신망법 위반이에요. 연습은 **내가 만든 프로그램, CTF, 워게임** 등 허용된 대상에서만 하세요.
