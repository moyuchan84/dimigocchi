## 핵심 개념 1 — AI, 머신러닝, 생성형 AI는 어떻게 다를까

IT 뉴스에서 가장 자주 보이는 세 단어입니다. 셋은 경쟁 관계가 아니라 **큰 상자 안에 작은 상자가 들어 있는 관계**예요.

```
┌─────────────────────────────────────────┐
│ 인공지능 (AI)                            │
│  = 사람처럼 판단·인식하게 만드는 기술 전체  │
│  ┌───────────────────────────────────┐  │
│  │ 머신러닝                           │  │
│  │  = 데이터를 보고 스스로 규칙을 찾음  │  │
│  │  ┌─────────────────────────────┐  │  │
│  │  │ 딥러닝                       │  │  │
│  │  │  = 여러 층의 신경망을 사용    │  │  │
│  │  │  ┌───────────────────────┐  │  │  │
│  │  │  │ 생성형 AI              │  │  │  │
│  │  │  │  = 새 결과물을 만들어냄 │  │  │  │
│  │  │  └───────────────────────┘  │  │  │
│  │  └─────────────────────────────┘  │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

### 규칙을 "짜 넣는" 것과 "찾아내는" 것의 차이

예전 방식은 사람이 규칙을 직접 코드로 적었습니다. "이메일에 '무료 당첨'이라는 말이 있으면 스팸으로 분류하라" 하는 식이죠. 그런데 스팸을 보내는 쪽이 표현을 조금만 바꾸면 바로 뚫립니다.

**머신러닝**은 접근이 다릅니다. 스팸으로 판정된 메일과 정상 메일을 잔뜩 보여 주면, 컴퓨터가 **어떤 특징이 스팸과 관련 있는지 스스로 계산**해 냅니다. 사람이 규칙을 적는 게 아니라 데이터에서 규칙이 나오는 거예요.

**생성형 AI**는 여기서 한 걸음 더 나갑니다. 분류하거나 예측하는 데 그치지 않고 **없던 결과물을 새로 만들어 냅니다.** 글, 그림, 코드, 음성처럼요.

### 뉴스를 읽을 때 붙잡을 두 가지 질문

- **어떤 데이터로 배웠나?** 학습에 쓴 데이터가 편향돼 있으면 결과도 편향됩니다. 이걸 **AI 편향**이라고 불러요.
- **틀렸을 때 누가 책임지나?** AI가 사실이 아닌 내용을 그럴듯하게 지어내는 현상을 **환각(할루시네이션)** 이라 합니다. 그래서 의료·법률처럼 중요한 분야일수록 사람의 확인이 필수예요.

## 핵심 개념 2 — 빅데이터와 클라우드

### 빅데이터 — 크기보다 "다루는 방식"이 핵심

빅데이터는 그냥 "데이터가 많다"는 뜻이 아니라, **기존 방식으로는 감당이 안 될 만큼 크고 빠르고 다양한 데이터**를 가리킵니다. 흔히 3V로 설명해요.

| 특징 | 뜻 | 예 |
|---|---|---|
| Volume(양) | 저장 용량이 매우 큼 | 전 세계 사용자의 클릭 기록 |
| Velocity(속도) | 실시간으로 쏟아짐 | 초 단위로 들어오는 센서 값 |
| Variety(다양성) | 형태가 제각각 | 표, 사진, 영상, 댓글이 뒤섞임 |

빅데이터와 AI는 붙어 다닙니다. **머신러닝이 배울 재료가 바로 데이터**이기 때문이에요. "데이터가 많은 회사가 AI를 잘한다"는 말이 나오는 이유입니다.

### 클라우드 — 한마디로 "남의 컴퓨터를 빌려 쓴다"

내 컴퓨터에 프로그램을 깔고 파일을 저장하는 대신, **인터넷 너머에 있는 남의 컴퓨터(데이터센터)를 빌려 쓰는 방식**입니다. 전기를 쓰려고 집집마다 발전기를 두지 않고 발전소에서 끌어다 쓰는 것과 같아요.

빌려 쓰면 뭐가 좋을까요?

- **필요한 만큼만 쓴다** — 이용자가 늘면 서버를 늘리고, 줄면 줄인다. 쓴 만큼만 낸다.
- **초기 비용이 적다** — 서버를 직접 사서 관리할 필요가 없다.
- **어디서든 접근한다** — 인터넷만 되면 같은 파일을 폰에서도 노트북에서도 본다.

대신 단점도 분명합니다.

- **인터넷이 끊기면 못 쓴다.**
- **내 데이터가 남의 서버에 있다** — 그래서 클라우드 보안이 중요한 주제가 됩니다.
- **그 회사에 문제가 생기면 나도 멈춘다** — 큰 클라우드 서비스에 장애가 나면 관련 서비스가 한꺼번에 먹통이 되는 뉴스를 종종 볼 수 있어요.

## 핵심 개념 3 — IoT와 개인정보 보호

### IoT — 컴퓨터가 아니었던 것들이 인터넷에 붙는다

IoT(사물인터넷)는 **일상 사물에 센서와 통신 기능을 넣어 인터넷에 연결하는 것**입니다. 스마트 스피커, 로봇청소기, 스마트워치, 도로의 교통 센서 모두 IoT예요.

보안 관점에서 IoT가 중요한 이유가 있습니다.

- 기기 수가 아주 많고, 한번 설치하면 **몇 년씩 업데이트 없이 방치**되기 쉽습니다.
- 화면과 키보드가 없어 **비밀번호를 바꾸기 번거롭고**, 공장 초기 비밀번호가 그대로인 경우가 많습니다.
- 그래서 공격자가 IoT 기기를 노려 **집 안 네트워크로 들어오는 입구**로 삼으려 합니다.

방어의 기본은 단순합니다. **초기 비밀번호를 반드시 바꾸고, 펌웨어를 업데이트하고, 쓰지 않는 기능은 꺼 두는 것.** 해킹방어과 면접에서 "IoT 보안"이 나오면 이 세 가지를 말할 수 있으면 충분히 좋은 답변이에요.

### 개인정보 — 누구인지 알아볼 수 있으면 개인정보다

**개인정보**란 살아 있는 개인을 **알아볼 수 있게 하는 정보**를 말합니다. 이름·주민등록번호처럼 그 자체로 특정되는 것뿐 아니라, **다른 정보와 합치면 누구인지 알 수 있는 것**도 포함돼요. 우리나라에는 이를 다루는 **개인정보 보호법**이 있고, 관련 정책을 담당하는 **개인정보보호위원회**가 있습니다.

기억해 둘 원칙 네 가지입니다.

| 원칙 | 뜻 |
|---|---|
| 최소 수집 | 서비스에 꼭 필요한 정보만 모은다 |
| 목적 제한 | 모을 때 밝힌 목적 외에는 쓰지 않는다 |
| 동의 | 수집·이용에는 본인의 동의가 필요하다 |
| 안전 조치 | 암호화·접근 통제로 지키고, 목적이 끝나면 파기한다 |

자주 나오는 두 단어도 함께 기억하세요.

- **비식별화(가명·익명 처리)** — 누구인지 알아볼 수 없게 가공하는 것. 연구나 통계에 쓰려고 처리합니다.
- **개인정보 유출** — 이름·연락처·비밀번호 등이 외부로 새어 나가는 사고. 유출된 정보가 다른 사이트 로그인 시도(**크리덴셜 스터핑**)에 쓰이기 때문에, **사이트마다 다른 비밀번호를 쓰는 습관**이 그래서 중요합니다.

## 예시 — 뉴스 스크랩 노트 만들기

IT 시사 문제와 면접 질문은 "얼마나 많이 외웠나"보다 **"자기 생각을 정리해 봤나"** 를 봅니다. 그래서 뉴스를 읽고 짧게 정리해 두는 습관이 그대로 실력이 돼요.

### 자주 보이는 용어 미리 정리

| 용어 | 한 줄 뜻 |
|---|---|
| 생성형 AI | 글·그림·코드 같은 새 결과물을 만들어 내는 AI |
| 할루시네이션 | AI가 사실이 아닌 내용을 그럴듯하게 만들어 내는 현상 |
| 클라우드 | 인터넷 너머의 컴퓨터 자원을 빌려 쓰는 방식 |
| 빅데이터 | 기존 방식으로 처리하기 어려운 규모·속도·형태의 데이터 |
| IoT | 일상 사물을 인터넷에 연결한 것 |
| 랜섬웨어 | 파일을 암호화해 잠근 뒤 금전을 요구하는 악성 프로그램 |
| 피싱 | 진짜인 척 속여 계정·금융 정보를 빼내는 공격 |
| 개인정보 유출 | 개인을 알아볼 수 있는 정보가 외부로 새어 나간 사고 |
| 제로트러스트 | "내부망이라도 일단 의심한다"는 보안 설계 원칙 |

### 스크랩 노트 3칸 양식

기사 하나에 **딱 세 칸**만 채우세요. 길게 쓰려다 안 하게 되는 것보다 짧게라도 꾸준한 게 낫습니다.

```
[날짜]  2026-07-30
[제목]  (기사 제목과 출처 언론사)

1. 무슨 일이 있었나 (사실만, 2~3줄)
   - 누가 / 무엇을 / 언제

2. 왜 중요한가 (영향, 2~3줄)
   - 누구에게 어떤 영향이 있나
   - 보안 관점에서 짚을 점은 무엇인가

3. 내 생각 (2~3줄)
   - 나는 이 사안을 어떻게 보나
   - 근거는 무엇인가
```

### 채우는 요령

- **1번 칸에는 사실만** 적습니다. 의견을 섞으면 나중에 무엇이 사실이었는지 헷갈려요.
- **3번 칸은 반드시 채웁니다.** 면접에서 묻는 건 사실이 아니라 생각이에요. "찬성/반대"보다 "이런 점은 좋지만 이런 점은 걱정된다"처럼 **양쪽을 보고 근거를 대는 답**이 훨씬 좋습니다.
- 일주일에 **2~3건이면 충분합니다.** 주제를 AI·보안 사고·개인정보로 나눠 모아 두면 면접 직전에 최고의 복습 자료가 됩니다.
- 이 챕터의 개념 설명은 뼈대일 뿐입니다. **구체적인 사건과 수치는 반드시 최근 뉴스에서 직접 확인**하세요. 확실하지 않은 숫자를 면접에서 말하는 것은 모른다고 하는 것보다 위험합니다.

## 확인 문제

**문제 1.** "머신러닝"과 "생성형 AI"의 관계를 한 문장으로 설명해 보세요.

<details>
<summary>정답 확인</summary>

**정답:** 생성형 AI는 머신러닝(그중에서도 딥러닝)에 속하는 한 갈래로, 데이터를 학습한다는 점은 같지만 분류·예측에 그치지 않고 **새로운 결과물을 만들어 낸다**는 점이 다릅니다.

**해설:** 셋의 포함 관계를 "AI ⊃ 머신러닝 ⊃ 딥러닝 ⊃ 생성형 AI"로 기억하세요. 면접에서 용어를 나란히 놓고 물으면 대부분 **상하 관계와 차이점**을 묻는 것입니다.

</details>

**문제 2.** 스마트 홈 기기를 새로 샀습니다. 보안을 위해 가장 먼저 해야 할 일 세 가지는 무엇일까요?

<details>
<summary>정답 확인</summary>

**정답:** ① 공장 초기 비밀번호를 바꾼다 ② 펌웨어를 최신으로 업데이트한다 ③ 쓰지 않는 원격 접속 기능은 꺼 둔다

**해설:** IoT 기기 사고의 상당수는 어려운 해킹 기술 때문이 아니라 **초기 설정을 그대로 둔 것**에서 시작합니다. 보안의 기본은 화려한 기술이 아니라 이런 기본 조치라는 점이 핵심이에요.

</details>

**문제 3.** 친구가 "클라우드에 올리면 내 컴퓨터가 고장 나도 안전하니까 아무거나 다 올려도 돼"라고 말합니다. 어떤 점을 짚어 주면 좋을까요?

<details>
<summary>정답 확인</summary>

**정답:** 기기 고장에는 강하지만, 데이터가 **남의 서버에 저장된다**는 사실은 변하지 않습니다. 계정이 털리거나 공유 설정을 잘못하면 그대로 노출되고, 서비스 자체에 장애나 유출 사고가 날 수도 있습니다.

**해설:** 클라우드는 **가용성**(기기가 망가져도 접근 가능)에는 유리하지만 **기밀성**(나만 볼 수 있음)을 자동으로 보장해 주지는 않습니다. 그래서 강한 비밀번호와 2단계 인증, 공유 링크 관리가 함께 가야 해요. 이렇게 "장점은 인정하되 조건을 붙여 말하는" 답변 방식이 면접에서 좋은 인상을 줍니다.

</details>

## 요약

- **AI ⊃ 머신러닝 ⊃ 딥러닝 ⊃ 생성형 AI** 의 포함 관계로 기억한다. 머신러닝은 데이터에서 규칙을 스스로 찾고, 생성형 AI는 새 결과물을 만들어 낸다.
- **빅데이터**는 단순히 양이 많은 게 아니라 양·속도·다양성 때문에 기존 방식으로 다루기 어려운 데이터다. AI가 배울 재료가 된다.
- **클라우드**는 "남의 컴퓨터를 빌려 쓰는 것". 비용과 확장성에서 유리하지만 데이터가 외부에 있다는 점에서 보안이 중요해진다.
- **IoT**는 기기 수가 많고 방치되기 쉬워 초기 비밀번호 변경·펌웨어 업데이트·불필요한 기능 끄기가 방어의 기본이다.
- **개인정보**는 개인을 알아볼 수 있는 정보이며, 최소 수집·목적 제한·동의·안전 조치가 원칙이다.
- 뉴스는 **무슨 일이 / 왜 중요한지 / 내 생각** 세 칸으로 정리하고, 구체적인 사건과 수치는 최근 기사에서 직접 확인한다.
