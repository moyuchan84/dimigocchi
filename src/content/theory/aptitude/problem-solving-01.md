## 핵심 개념

### 알고리즘은 "누가 따라 해도 같은 결과가 나오는 설명서"

라면 봉지 뒷면을 떠올려 보세요.

```text
1. 물 550mL 를 끓인다
2. 면과 스프를 넣는다
3. 4분 30초 더 끓인다
4. 불을 끈다
```

누가 읽어도 같은 순서로, 같은 결과를 얻어요. **알고리즘**은 이렇게 어떤 문제를 풀기 위한 **순서가 정해진 단계들의 모음**이에요.

다만 알고리즘이라고 부르려면 조건이 몇 가지 있어요.

| 조건 | 뜻 | 어긋난 예 |
|---|---|---|
| **명확성** | 각 단계가 애매하지 않다 | "적당히 끓인다" |
| **유한성** | 언젠가 반드시 끝난다 | "물이 끓을 때까지 기다린다"인데 불을 안 켰다 |
| **입력** | 필요한 재료가 주어진다 | 라면이 없다 |
| **출력** | 결과가 나온다 | 끓이기만 하고 안 먹는다 |

"적당히", "알아서", "잘" 같은 말이 들어가면 알고리즘이 아니에요. 컴퓨터는 눈치가 전혀 없어서 **애매한 지시를 스스로 채워 넣지 못하거든요.**

### 같은 문제, 다른 알고리즘

문제 하나에 알고리즘은 여러 개일 수 있어요. 1부터 100까지 더하는 문제를 봅시다.

**방법 A — 하나씩 더하기**: 1 + 2 + 3 + … + 100. 덧셈을 99번 해요.

**방법 B — 짝 지어 더하기**: 1과 100, 2와 99 … 처럼 짝을 지으면 합이 모두 101이고 짝이 50개예요. `101 × 50 = 5050`. 계산 두 번이면 끝나요.

둘 다 정답 5050을 내지만 **B가 훨씬 빨라요**. 알고리즘을 배우는 이유가 여기 있어요. 답을 내는 것만이 아니라 **더 적은 일로 답을 내는 것**이 목표입니다.

### 순서도 기호

**순서도(flowchart)** 는 알고리즘을 그림으로 그린 거예요. 기호마다 뜻이 정해져 있고, 시험에 그대로 나옵니다.

| 기호 모양 | 이름 | 하는 일 |
|---|---|---|
| 둥근 타원 | 단말(터미널) | 시작과 끝 |
| 평행사변형 | 입출력 | 값을 받거나 결과를 보여줌 |
| 직사각형 | 처리 | 계산, 값 저장 |
| **마름모** | **판단(조건)** | 예/아니오로 갈라짐 |
| 화살표 | 흐름선 | 다음으로 갈 방향 |

**마름모가 핵심**이에요. 순서도에서 길이 갈라지는 곳은 오직 마름모뿐이고, 마름모에서 나가는 화살표에는 반드시 **예(Yes) / 아니오(No)** 표시가 붙어요.

짝수·홀수를 판별하는 순서도를 글로 그려 볼게요.

```text
   (시작)
      ↓
 [ N 을 입력받는다 ]        ← 평행사변형
      ↓
 < N 을 2로 나눈 나머지가 0인가? >   ← 마름모
   ↓ 예              ↓ 아니오
 [ "짝수" 출력 ]   [ "홀수" 출력 ]
   ↓                 ↓
      →  (끝)  ←
```

두 갈래로 갈라졌다가 다시 하나로 모여 끝나죠. 순서도를 볼 때는 **화살표를 손가락으로 짚으며 따라가세요.** 눈으로만 보면 반드시 길을 잃습니다.

### 의사코드 — 사람이 읽는 프로그램

**의사코드(pseudocode)** 는 실제 프로그래밍 언어는 아니지만 프로그램처럼 생긴 글이에요. 문법을 몰라도 읽히도록 쓴 설계도죠. 적성검사에서는 특정 언어를 몰라도 풀 수 있게 의사코드로 문제를 냅니다.

```text
합계 ← 0
i ← 1
i 가 10 이하인 동안 반복:
    합계 ← 합계 + i
    i ← i + 1
합계 를 출력
```

`←` 는 "오른쪽 값을 왼쪽 상자에 넣어라"는 뜻이에요. `합계 ← 합계 + i` 는 등식이 아니라 **명령**이에요. "지금 합계에 i를 더한 값을 다시 합계에 넣어라"는 뜻이죠. 수학의 `=` 처럼 읽으면 절대 이해할 수 없어요. 여기서 막히는 사람이 많으니 꼭 기억하세요.

### 구조는 세 가지뿐

아무리 복잡한 프로그램도 이 세 가지 구조의 조합이에요.

**1. 순차** — 위에서 아래로 한 줄씩.

```text
A 를 한다
B 를 한다
C 를 한다
```

**2. 선택(조건)** — 조건에 따라 갈라짐.

```text
만약 점수 >= 60 이면:
    "합격" 출력
아니면:
    "불합격" 출력
```

**3. 반복** — 조건이 참인 동안 되풀이.

```text
i ← 1
i 가 5 이하인 동안 반복:
    i 를 출력
    i ← i + 1
```

반복 구조에는 반드시 **끝나는 장치**가 있어야 해요. 위 예에서 `i ← i + 1` 이 없으면 i가 영원히 1이라 조건이 계속 참이 되고, 프로그램이 멈추지 않아요. 이런 걸 **무한 루프**라고 해요. 알고리즘의 조건 중 '유한성'을 어긴 거죠.

## 예시

### 예시 1 — 의사코드 결과 예측하기

시험에 가장 많이 나오는 유형이에요. 방법은 하나뿐입니다. **표를 그려서 값을 하나씩 적으세요.**

```python
x = 0
n = 1
while n <= 4:
    x = x + n * 2
    n = n + 1
print(x)
```

머릿속으로 굴리지 말고, 반복이 한 바퀴 돌 때마다 값을 적어요.

| 바퀴 | 반복 전 n | 반복 전 x | x = x + n×2 | 반복 후 n |
|---|---|---|---|---|
| 1 | 1 | 0 | 0 + 2 = 2 | 2 |
| 2 | 2 | 2 | 2 + 4 = 6 | 3 |
| 3 | 3 | 6 | 6 + 6 = 12 | 4 |
| 4 | 4 | 12 | 12 + 8 = 20 | 5 |

n이 5가 되면 `n <= 4` 가 거짓이라 반복이 끝나요. 출력은 **20**.

이 표를 **추적표**라고 해요. 손으로 표를 그리는 30초가 머리로 계산하다 틀리는 것보다 훨씬 빠릅니다.

### 예시 2 — 조건이 겹칠 때

```python
score = 85
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "D"
print(grade)
```

`elif` 는 "앞의 조건이 거짓일 때만 확인한다"는 뜻이에요. 85는 첫 조건(90 이상)에서 걸리지 않고, 두 번째 조건(80 이상)에서 참이 되어 **B** 가 됩니다. 그 뒤 조건들은 아예 확인하지 않아요.

여기서 함정이 하나 있어요. 만약 순서를 이렇게 바꾸면 어떻게 될까요?

```python
if score >= 70:
    grade = "C"
elif score >= 80:
    grade = "B"
```

85점인데도 첫 조건에서 걸려 **C** 가 나와요. **조건 검사에서는 순서가 결과를 바꿉니다.** 범위 조건은 좁은 것(큰 값)부터 쓰는 게 안전해요.

### 예시 3 — 디버깅형 문제 접근법

"다음 코드는 1부터 5까지의 합(15)을 구하려 했지만 결과가 다르다. 잘못된 곳은?"

```python
total = 0
i = 1
while i < 5:
    total = total + i
    i = i + 1
print(total)
```

**1단계, 무엇을 하려는지 먼저 확인해요.** 목표는 1+2+3+4+5 = 15.

**2단계, 추적표를 그려요.**

| 바퀴 | i | 조건 i < 5 | total |
|---|---|---|---|
| 1 | 1 | 참 | 1 |
| 2 | 2 | 참 | 3 |
| 3 | 3 | 참 | 6 |
| 4 | 4 | 참 | 10 |
| 5 | 5 | **거짓 → 종료** | 10 |

**3단계, 어긋난 지점을 짚어요.** 5가 더해지기 전에 반복이 끝났어요. 원인은 조건 `i < 5` — `i <= 5` 여야 합니다. 이렇게 경계에서 한 번 덜 돌거나 더 도는 실수를 **하나 차이 오류**라고 하고, 프로그래밍에서 가장 흔한 버그예요.

디버깅형 문제에서 범인은 대개 이 넷 중 하나예요.

- **비교 연산자**: `<` 와 `<=` 를 바꿔 씀
- **초기값**: 합계를 0이 아닌 값으로 시작, 시작 번호가 1이 아니라 0
- **증가 위치**: `i = i + 1` 을 빠뜨림(무한 루프) 또는 엉뚱한 위치에 둠
- **조건 순서**: 예시 2처럼 넓은 조건을 먼저 검사

의심 가는 줄을 **하나만 고쳐 보고 추적표를 다시 돌리세요.** 여러 곳을 한꺼번에 고치면 무엇이 원인이었는지 알 수 없어요.

### 예시 4 — 문제를 알고리즘으로 바꾸는 연습

"세 수 중 가장 큰 수를 찾아라"를 의사코드로 써 볼게요.

```text
A, B, C 를 입력받는다
최댓값 ← A
만약 B > 최댓값 이면:
    최댓값 ← B
만약 C > 최댓값 이면:
    최댓값 ← C
최댓값 을 출력
```

핵심은 **"일단 첫 번째를 챔피언으로 정해 두고, 도전자가 더 크면 자리를 바꾼다"** 는 발상이에요. 이 방식은 수가 3개든 100개든 그대로 통해요. 반면 "A와 B와 C를 모두 비교하는 조건을 다 나열하는" 방식은 수가 늘어나면 감당할 수 없죠.

좋은 알고리즘은 **개수가 늘어나도 구조가 그대로인 알고리즘**이에요.

## 확인 문제

**문제 1.** 다음 의사코드의 출력값은?

```python
s = 0
k = 3
while k <= 9:
    s = s + k
    k = k + 3
print(s)
```

<details>
<summary>정답 확인</summary>

**정답:** 18

**해설:** 추적표를 그려 봅시다.

| 바퀴 | k | 조건 k <= 9 | s |
|---|---|---|---|
| 1 | 3 | 참 | 0 + 3 = 3 |
| 2 | 6 | 참 | 3 + 6 = 9 |
| 3 | 9 | 참 | 9 + 9 = 18 |
| 4 | 12 | 거짓 → 종료 | 18 |

k가 3씩 커지므로 3, 6, 9 만 더해져요. `3 + 6 + 9 = 18` 입니다. k가 9일 때도 조건이 참이라 **9가 포함된다**는 점을 놓치지 마세요.

</details>

**문제 2.** 순서도에서 "예/아니오로 흐름이 갈라지는 곳"에 쓰는 기호는 무엇이며, 그 모양은 어떤가요?

<details>
<summary>정답 확인</summary>

**정답:** 판단(조건) 기호이며, 모양은 마름모입니다.

**해설:** 순서도 기호는 역할별로 모양이 정해져 있어요.

- 둥근 타원 = 시작/끝
- 평행사변형 = 입력/출력
- 직사각형 = 처리(계산·값 저장)
- **마름모 = 판단(조건)**

흐름이 갈라지는 곳은 마름모뿐이고, 나가는 화살표에는 예/아니오를 반드시 표시해요. 직사각형(처리)에서 화살표가 두 개 나가면 잘못 그린 순서도입니다.

</details>

**문제 3.** 다음 코드는 1부터 10까지의 짝수의 합(30)을 구하려 한 것인데 결과가 다릅니다. 어디를 고쳐야 할까요?

```python
total = 0
i = 1
while i <= 10:
    if i % 2 == 1:
        total = total + i
    i = i + 1
print(total)
```

<details>
<summary>정답 확인</summary>

**정답:** `if i % 2 == 1` 을 `if i % 2 == 0` 으로 고쳐야 합니다.

**해설:** `%` 는 나눈 나머지를 구하는 기호예요. `i % 2 == 1` 은 **2로 나눈 나머지가 1**, 즉 홀수일 때만 더하라는 뜻이에요. 그래서 지금 코드는 1+3+5+7+9 = **25** 를 출력해요.

짝수는 2로 나눈 나머지가 0이므로 조건을 `i % 2 == 0` 으로 바꾸면 2+4+6+8+10 = 30 이 됩니다.

반복 범위(`i <= 10`)와 증가(`i = i + 1`)는 문제가 없어요. **목표값(30)과 실제값(25)의 차이를 보고 어느 수가 빠졌는지 되짚는 것**이 디버깅형 문제의 지름길이에요.

</details>

## 요약

- **알고리즘**은 문제를 푸는 순서가 정해진 단계들이며, **명확성·유한성·입력·출력**을 갖춰야 해요. "적당히" 같은 말이 들어가면 알고리즘이 아니에요.
- **순서도** 기호는 타원(시작/끝), 평행사변형(입출력), 직사각형(처리), **마름모(판단)**. 흐름이 갈라지는 곳은 마름모뿐이에요.
- 모든 프로그램은 **순차·선택·반복** 세 구조의 조합이에요. 반복에는 반드시 끝나는 장치가 있어야 무한 루프를 피할 수 있어요.
- 의사코드 결과를 물으면 머리로 굴리지 말고 **추적표를 손으로 그리세요.** 이게 가장 빠르고 정확해요.
- 디버깅형 문제의 단골 원인은 **비교 연산자(`<` vs `<=`), 초기값, 증가 위치, 조건 순서** 네 가지예요. 한 번에 한 곳만 고쳐 확인하세요.
